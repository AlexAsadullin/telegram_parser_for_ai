# Telegram Channel Parser

Инструмент для полной выгрузки данных из Telegram-канала и хранения их в структурированном виде для AI-аналитики.

## Возможности

**Каналы**

- Скачивает все посты канала в хронологическом порядке
- Сохраняет фото, видео, кружочки, голосовые сообщения и файлы
- Транскрибирует голосовые сообщения через Telegram API (требуется Telegram Premium)

**Личные сообщения**

- Скачивает переписку целиком и распознаёт речь **локально**, без Telegram Premium
- Голосовые сообщения и кружки превращаются в текст и встают в общую хронологию чата вместе с обычными сообщениями
- Из кружка берётся только аудиодорожка — видео не сохраняется
- Обрабатывает чат чанками и пишет результат потоком на диск, поэтому длина переписки не влияет на потребление памяти

**Общее**

- Показывает прогресс загрузки в реальном времени
- Ведёт историю запросов в SQLite
- Экспортирует в единый `.txt` файл, оптимизированный для чтения LLM

## Стек

| Слой | Технологии |
|---|---|
| Backend | Python 3.13, FastAPI 0.141, Telethon 1.44, aiosqlite, uvicorn |
| Распознавание речи | MLX (Apple GPU) или faster-whisper (CPU), модель `small` |
| Frontend | React 19, Vite 8, Axios |
| Хранение | JSON / JSONL-файлы + SQLite |

### Распознавание речи: GPU или CPU

Два движка, выбор автоматический (`WHISPER_BACKEND=auto`):

| Движок | Устройство | Когда используется |
|---|---|---|
| **mlx-whisper** | GPU Apple M-серии | Apple Silicon — выбирается по умолчанию |
| **faster-whisper** | CPU | Всё остальное, либо принудительно |

Замер на **MacBook Air M2**, 30 с русской речи, модель `small`:

| | время | к реальному времени |
|---|---|---|
| faster-whisper, CPU int8 | 4.02 с | ×7.6 |
| **mlx-whisper, GPU** | **1.60 с** | **×19.1** |

GPU-путь быстрее в **2.6 раза**. Проверено, что MLX действительно работает на видеоядре: `mlx.core.default_device()` возвращает `Device(gpu, 0)`.

> **faster-whisper не умеет в GPU на Mac** — это ограничение библиотеки, а не настройка. CTranslate2 собран без CUDA и не имеет бэкенда Metal, поэтому `device="mps"`, `"metal"` и `"gpu"` отклоняются с `unsupported device`. Именно поэтому для GPU добавлен отдельный движок MLX, а не изменён параметр.

Какой движок активен, видно в интерфейсе (бейдж под полем ввода) и в `GET /api/asr-model`.

Принудительный выбор: `WHISPER_BACKEND=faster-whisper` или `WHISPER_BACKEND=mlx`.

### Почему `small`

Проверено на русской речи: `base` (141 МБ) искажает термины — «парсинг телеграм» превращается в «Парсин-Птелегром». `small` (464 МБ) распознаёт ту же фразу дословно. Модель скачивается автоматически при первой транскрибации и кешируется в `~/.cache/huggingface`.

Размер модели меняется переменной `WHISPER_MODEL` — доступны `tiny`, `base`, `small`, `medium`, `large-v3`. Для MLX имя автоматически разворачивается в репозиторий `mlx-community/whisper-{модель}-mlx`.

Отдельный `ffmpeg` не нужен ни в одном режиме: звук декодируется через PyAV — и для `.ogg` голосовых, и для `.mp4` кружков. Собственный загрузчик MLX вызвал бы внешний `ffmpeg`, поэтому ему передаётся уже декодированный массив.

## Запуск одной командой

Из корня проекта:

```bash
./run.sh
```

Скрипт поднимает бэкенд на `:8000` и фронтенд на `:5173`, дожидается готовности обоих и печатает ссылку. Откройте [http://localhost:5173](http://localhost:5173).

**Остановка — `Ctrl+C`** в том же терминале: гасятся оба сервера. Если терминал закрыт или что-то пережило родителя:

```bash
./stop.sh
```

Порты можно переопределить:

```bash
BACKEND_PORT=8001 FRONTEND_PORT=5174 ./run.sh
```

При первом запуске `run.sh` сам поставит зависимости фронтенда. Если чего-то не хватает — нет `venv`, нет `.env`, занят порт — скрипт скажет, что именно, и не станет запускаться наполовину.

Ручной запуск в двух терминалах по-прежнему возможен, он описан в разделе «Быстрый старт» ниже.

## Вход в Telegram

Авторизация происходит **в браузере**, заходить в терминал не нужно.

При первом открытии приложение проверяет сессию и, если входа нет, показывает окно логина:

1. Номер телефона → Telegram присылает код.
2. Код из Telegram.
3. Облачный пароль — только если на аккаунте включена двухфакторная защита.

После входа сессия сохраняется в `backend/session/`, и повторно вводить ничего не нужно. Текущий аккаунт и кнопка **«Выйти»** — в шапке приложения.

Номер, код и пароль уходят только на ваш локальный бэкенд и оттуда в Telegram. Эндпоинты входа доступны лишь с `localhost:5173` и `localhost:4173` — CORS намеренно сужен, чтобы страница в соседней вкладке не могла управлять входом.

> Для headless-сценариев остался и терминальный вход: `python -m backend.login`. Он не обязателен.

# Сколько сообщений обрабатывается за один чанк

### 3. Backend

Проект использует Python 3.13 и уже подготовленный `venv`.

> Все команды ниже выполняются **из корня проекта** — `backend` импортируется как пакет (`backend.main`), поэтому запуск из каталога `backend/` не сработает.

Активировать окружение:

```bash
source venv/bin/activate
```

Установить/обновить зависимости (при первом запуске и после обновления `requirements.txt`):

```bash
pip install -r requirements.txt
```

Запустить сервер:

```bash
uvicorn backend.main:app --reload
```

Авторизация в Telegram делается **в браузере** — см. раздел «Вход в Telegram» ниже. Терминал для этого не нужен.

Сервер будет доступен на `http://localhost:8000`. Это **только API** — интерфейса там нет, корень перенаправляет на Swagger UI (`/docs`). Веб-интерфейс живёт на порту 5173, см. следующий шаг.

### 4. Frontend

Бэкенд из шага 3 **остаётся работать** — фронтенд запускается в отдельном терминале, параллельно. Нужны оба процесса сразу.

Установите зависимости (только при первом запуске):

```bash
cd frontend
npm install
```

Запустите dev-сервер:

```bash

```

Откройте браузер: [http://localhost:5173](http://localhost:5173)

Дополнительно: `npm run lint` — проверка кода, `npm run build` — production-сборка в `frontend/dist/`.

## Использование

На главном экране две вкладки: **«Канал»** и **«Личные сообщения»**.

### Скачать канал

1. На вкладке **«Канал»** вставьте любой из форматов:
   - `@username`
   - `https://t.me/username`
   - `https://t.me/username/123` (ссылка на конкретный пост)
   - `https://t.me/+InviteHash` (приватный канал)
   - числовой ID канала

2. Нажмите **«Скачать канал»** — прогресс отображается в реальном времени.

3. Данные сохраняются в `data/{channel_id}/`.

### Скачать личную переписку

1. Откройте вкладку **«Личные сообщения»**. Ниже поля ввода подгружается список ваших личных чатов — можно кликнуть по нужному вместо ручного ввода.

2. Либо введите вручную: `@username`, числовой ID пользователя или `me` для «Избранного».

3. Нажмите **«Скачать переписку»**. Голосовые и кружки распознаются локальной моделью, поэтому на них прогресс идёт медленнее обычного текста.

   Во время работы видно, чем именно занят бэкенд: загрузка модели, скачивание конкретного медиа, распознавание («распознаю кружок 0:08»). Отдельная полоса показывает прогресс именно по речи — в секундах звука и в числе распознанных сообщений. Это важно, потому что счётчик сообщений и объём речи движутся с разной скоростью: одно голосовое на 5 минут весит больше двухсот текстовых.

4. Кнопка **«Остановить скачивание»** прерывает процесс. Всё, что успело сохраниться по этому чату, удаляется — каталог `data/dm_{user_id}/` стирается целиком.

   Это не «пауза»: продолжить с места остановки нельзя, потому что частично выгруженный чат неотличим от полного. Запуск начинается заново. Кнопка спрашивает подтверждение.

   Для каналов кнопка работает так же и удаляет `data/{channel_id}/` — вместе с уже скачанными медиафайлами, в том числе от предыдущих запусков.

4. Данные сохраняются в `data/dm_{user_id}/`.

5. Готовые переписки — кнопка **«Скачанные переписки»** в правом верхнем углу, оттуда же выгружается `.txt`.

Распознанная речь попадает в ту же хронологию, что и обычные сообщения:

```
[2024-01-15 10:02:00] Я: Нормально, сейчас голосовым отвечу
[2024-01-15 10:03:00] Я [голосовое, 5с]: Привет, сегодня я хочу рассказать про парсинг...
[2024-01-15 10:04:00] Тест Тестов: Понял тебя
[2024-01-15 10:05:00] Тест Тестов [кружок, 5с]: Привет! Сегодня я хочу рассказать про...
```

Если распознать речь не удалось, сообщение помечается `[голосовое, не распознано]` и не теряется.

### Скачать канал без фронтенда

Фронтенд не обязателен — парсинг запускается через HTTP API работающего бэкенда.

Запустить задачу — в ответ придёт `{"task_id": "..."}`:

```bash
curl -X POST http://localhost:8000/api/parse \
  -H "Content-Type: application/json" \
  -d '{"channel": "@username"}'
```

Следить за прогрессом (подставьте полученный `task_id`):

```bash
curl http://localhost:8000/api/status/TASK_ID
```

Забрать текстовый экспорт (подставьте `channel_id` из `data/`):

```bash
curl -OJ "http://localhost:8000/api/channels/CHANNEL_ID/export"
```

Личная переписка запускается так же, только другим эндпоинтом:

```bash
curl -X POST http://localhost:8000/api/parse-dm \
  -H "Content-Type: application/json" \
  -d '{"dialog": "@username"}'
```

И выгружается по ID пользователя:

```bash
curl -OJ "http://localhost:8000/api/dms/USER_ID/export"
```

То же самое интерактивно доступно в Swagger UI: `http://localhost:8000/docs`.

### Выгрузить текст

1. Нажмите **«Скачанные каналы»** в правом верхнем углу.
2. Выберите канал.
3. **«Выгрузить текст»** — скачивает `.txt` файл с хронологией постов (новые → старые).
4. **«Текст + транскрипция»** — дополнительно транскрибирует голосовые сообщения через Telegram API (требует Telegram Premium на авторизованном аккаунте).

## Структура данных

```
data/
├── {channel_id}/          # канал
│   ├── info.json          # метаданные канала
│   ├── posts.json         # все посты (ключ = ISO 8601 timestamp)
│   ├── photos/
│   ├── videos/            # видео и кружочки
│   ├── voice/             # голосовые сообщения
│   └── files/             # прочие файлы
└── dm_{user_id}/          # личная переписка
    ├── info.json          # собеседник
    └── messages.jsonl     # по одному сообщению на строку, старые → новые
```

Каталоги личных переписок имеют префикс `dm_`, поэтому не смешиваются с каналами.

Медиафайлы личной переписки **не сохраняются**: голосовые и кружки скачиваются во временный каталог, живут там до конца обработки всего чата и удаляются вместе с ним. На диске остаётся только распознанный текст.

**`info.json`**

```json
{
  "id": 1234567890,
  "title": "Название канала",
  "username": "username",
  "link": "https://t.me/username",
  "type": "public",
  "description": "Описание",
  "subscribers": 12345
}
```

**`posts.json`**

```json
{
  "2024-01-15T10:25:00": {
    "message_id": 42,
    "text": "Текст поста",
    "links": ["https://example.com"],
    "photos": ["photos/photo_123.jpg"],
    "videos": [],
    "voice": [],
    "files": []
  }
}
```

**`messages.jsonl`** — одна строка на сообщение, в хронологическом порядке. Распознанная речь лежит в том же поле `text`, что и напечатанный текст, а `kind` и `transcribed` говорят, откуда он взялся:

```json
{"message_id": 42, "date": "2024-01-15T10:03:00", "outgoing": true, "kind": "voice", "text": "привет, сегодня хочу рассказать...", "transcribed": true, "duration": 5}
{"message_id": 43, "date": "2024-01-15T10:04:00", "outgoing": false, "kind": "text", "text": "Понял тебя", "transcribed": false, "duration": null}
```

Формат построчный именно для того, чтобы и запись при парсинге, и чтение при экспорте шли потоком, без загрузки чата в память целиком.

## Формат текстового экспорта

Файл оптимизирован для передачи в LLM (Claude, GPT и др.):

```
────────────────────────────────────────────────────────────
КАНАЛ: @username — Название канала
ТИП: публичный | ПОДПИСЧИКОВ: 12 345
ЭКСПОРТ: 2024-01-15 10:30:00 UTC | ПОСТОВ: 234
────────────────────────────────────────────────────────────

[2024-01-15 10:25:00]
Текст поста.
[медиа: 2 фото]

[2024-01-14 18:00:00]
[голосовое сообщение]
[транскрипция: "привет, сегодня хочу рассказать..."]

[2024-01-13 09:00:00]
Только текст, без медиа.

────────────────────────────────────────────────────────────
```

Личная переписка выгружается как диалог — старые сообщения сверху:

```
────────────────────────────────────────────────────────────
ЛИЧНЫЙ ЧАТ: Иван Иванов (@ivan)
ЭКСПОРТ: 2024-01-15 10:30:00 UTC | СООБЩЕНИЙ: 842 | РАСПОЗНАНО ГОЛОСОМ: 57
────────────────────────────────────────────────────────────

[2024-01-15 10:01:00] Иван Иванов: Привет, как дела?
[2024-01-15 10:02:00] Я: Нормально, сейчас голосовым отвечу
[2024-01-15 10:03:00] Я [голосовое, 12с]: привет, смотри какая идея...
[2024-01-15 10:05:00] Иван Иванов [кружок, 8с]: да, я как раз про это думал

────────────────────────────────────────────────────────────
```

## API

| Метод | Путь | Описание |
|---|---|---|
| `GET` | `/api/auth/status` | Авторизована ли сессия и под каким аккаунтом |
| `POST` | `/api/auth/send-code` | Запросить код на номер телефона |
| `POST` | `/api/auth/sign-in` | Подтвердить код |
| `POST` | `/api/auth/password` | Облачный пароль (2FA), если требуется |
| `POST` | `/api/auth/cancel` | Отменить начатый вход |
| `POST` | `/api/auth/logout` | Выйти и обнулить сессию |
| `POST` | `/api/parse` | Запустить скачивание канала |
| `POST` | `/api/parse-dm` | Запустить скачивание личной переписки |
| `WS` | `/ws/progress/{task_id}` | Прогресс в реальном времени (общий для обоих типов) |
| `GET` | `/api/status/{task_id}` | Текущий статус задачи |
| `POST` | `/api/tasks/{task_id}/stop` | Остановить скачивание и удалить сохранённое |
| `GET` | `/api/history` | История запросов из SQLite |
| `GET` | `/api/channels` | Список скачанных каналов |
| `GET` | `/api/dialogs` | Личные чаты аккаунта (кандидаты на скачивание) |
| `GET` | `/api/dms` | Список скачанных переписок |
| `GET` | `/api/dms/{id}/export` | Текстовый экспорт переписки (стримом) |
| `GET` | `/api/asr-model` | Какая модель распознавания настроена |
| `GET` | `/api/channels/{id}/export` | Скачать текстовый экспорт (`?transcribe=true` для транскрибации) |

Документация Swagger доступна на `http://localhost:8000/docs`.

## Примечания

- **Приватные каналы** — работают, если авторизованный аккаунт является участником канала.
- **Транскрибация голосовых** — использует официальный Telegram API (`messages.TranscribeAudio`). Требует Telegram Premium на аккаунте, через который запущен парсер. Без Premium кнопка всё равно доступна, но транскрипции не будет — сообщения отметятся как `[голосовое сообщение]`.
- **Сессия** — файл `backend/session/anon.session` хранит авторизацию. Не добавляйте его в git (уже в `.gitignore`). Путь задаётся `TG_SESSION` в `.env` и резолвится от корня проекта. Существование файла не гарантирует авторизацию: при выходе из аккаунта приложение само покажет окно входа заново.
- **Вход** — сервер держит одно подключение к Telegram открытым между шагами «получить код» и «подтвердить код», потому что `phone_code_hash` привязан к соединению. Если между шагами перезапустить бэкенд, код придётся запросить заново.
- **Скорость распознавания** — на M2 через GPU около 19× реального времени: минута голосового обрабатывается примерно за 3 секунды. На CPU — около 7.6×. Модель загружается один раз в начале парсинга (стадия «загружаю модель»), дальше переиспользуется. Инференс идёт в отдельном потоке, поэтому прогресс и WebSocket не подвисают.
- **Память** — сообщения обрабатываются чанками по `DM_CHUNK_SIZE` и пишутся на диск построчно, экспорт тоже стримится. Переписка на десятки тысяч сообщений не увеличивает потребление памяти.
- **Повторное скачивание переписки** — перезаписывает `messages.jsonl` целиком, распознавание запускается заново.
- **Остановка** — записывается в историю со статусом `failed` и пометкой «Остановлено пользователем», в таблице показывается как «Остановлен». Отдельного статуса в БД нет: колонка `status` ограничена `CHECK`-констрейнтом, появившимся раньше кнопки остановки, и менять его ради ярлыка не стали.
- **Повторное скачивание** — перезаписывает `posts.json` целиком. Для обновления частично скачанного канала просто запустите заново.
- **Копирование команд** — блоки выше содержат только команды, без комментариев. В интерактивном zsh (по умолчанию на macOS) опция `interactive_comments` выключена, поэтому вставленный вместе с командой хвост `# комментарий` попадёт в аргументы — например, `npm install # только первый раз` падает с `EINVALIDTAGNAME`. Если копируете команду с комментарием из другого источника, отрежьте его или выполните `setopt interactive_comments`.
